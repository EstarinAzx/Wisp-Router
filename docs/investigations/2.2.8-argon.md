### Other public seams checked

**Hooks:** [Pre/PostInvocation](https://antigravity.google/docs/hooks/#preinvocation) can inject system/user/ephemeral messages or a tool call to execute; PostInvocation can terminate the loop. PreToolUse exposes name/arguments and `stepIdx`, supports gating or argument changes, and PostToolUse reports execution errors. The documented fields do not expose original model call IDs, arbitrary assistant history, or a supplied tool result. A transcript path is a log reference, not a supported replay/import contract. No hook was installed and no private transcript format was reverse-engineered.

**MCP sampling:** The [versioned 2025-11-25 sampling contract](https://modelcontextprotocol.io/specification/2025-11-25/client/sampling) supports messages, tools and matching tool-use/result IDs, but requires the client to advertise `sampling` and `sampling.tools`. Model hints are advisory. The reviewed Google CLI/MCP docs and installed help do not establish those capabilities or pinned Argon/effort semantics. Generic MCP support is insufficient evidence. This protocol possibility remains unverified; no native handshake or sampling request was attempted, and this reference is not a claim about the CLI's negotiated MCP version.

**SDK:** The [current SDK setup](https://antigravity.google/docs/sdk/overview/) uses a Gemini API key or Google Cloud credentials. It still does not document the required existing personal-subscription route. No SDK was installed and no new auth mechanism was substituted.

### Exact prerequisite and remaining work

A2 needs a vendor-supported existing-subscription interface with evidence for **role-structured history, caller instruction policy, original parallel call IDs and caller-supplied results**, plus pinned Argon effort, cancellation, isolation and usage/error semantics. A public schema and a sanitized supported-client capability receipt could establish that seam; merely adding model names, translating step indices, reading native secrets or treating an MCP request ID as a model ID cannot.

There are two possible changes of direction, neither selected here: an explicitly separate native-agent delegation feature with changed history/tool ownership, or an API-key/Cloud-backed integration with different credentials/billing. Both change the approved release contract and require the user's choice before dependent implementation. More generation under the current evidence would not resolve the missing interface contract.
