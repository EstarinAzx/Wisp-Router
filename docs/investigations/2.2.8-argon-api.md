## A2b: stateless core and one-request transport

Observed **2026-10-14**, relay leg 15, starting at `f5d51ce48805258a9ed071aea2ed20246d680f4e`. **Verdict: `pureCoreEstablished` with synthetic fetch only.** [Request/result validation](../../packages/core/src/geminiInteractions.ts) and [transport](../../packages/core/src/geminiInteractionsClient.ts) are unregistered modules. The core sends exactly `gemini-4-argon`, low/medium/high effort (default medium), `stream:false`, `store:false`, `background:false`, and an optional positive output limit no greater than **65,536**. The caller supplies an already-resolved single instruction string. Tool definitions retain their existing `ToolSpec` names/schema; absent options remain absent.

Supported steps are text `user_input`/`model_output`, thoughts with optional signatures/text summaries, external function calls, and complete original-ID function result batches. All supported step objects, ordering and opaque strings survive unchanged. Duplicate/orphan/missing results and interruption within a result batch fail. Unsupported steps/content/options, annotations and step-level errors fail explicitly. The subset preserves schema optionality for content, signature and summary; it is deliberately narrower than the full beta API. It rejects non-JSON values, sparse arrays and executable serialization instead of silently dropping data.

Successful output must contain an explicit terminal status and a complete step array. `requires_action` requires at least one original external function call; `completed` cannot conceal outstanding calls. Incomplete/failed/cancelled/unknown states, unknown output and malformed usage fail before calls reach the consumer. Usage preserves the provider's optional fields verbatim: input is prompt/context tokens, cached is the cached part of the prompt, output is generated-response tokens, thought is thinking tokens, tool-use is tool-prompt tokens, and total is the provider's overall total. These counters are neither added together nor converted to zero-filled `BridgeUsage`.

Transport validates before IO, accepts an injected API key, and makes at most one POST to the fixed beta URL. Redirects and automatic retries are refused; safe HTTP status and parsed Retry-After milliseconds survive without upstream bodies/headers/exceptions. Cancellation is checked before dispatch, after body completion and after asynchronous cleanup. This promises only local cancellation/delivery suppression, not cancellation of Google compute or billing.

### Persistent ownership and lifetime

The reserved field is `auth.geminiApi = { version: 1, lifetime, replayKey, apiKey }`. `lifetime` is 16 random bytes and `replayKey` 32 random bytes, each canonical unpadded base64url. The API key is a nonempty printable-ASCII string without spaces/control characters. The bundle is validated as a whole; malformed/partial records are unavailable and cannot be silently replaced. It is separate from `auth.keys`, OAuth records and `bridgeSecret`.

Both hosts read the same bundle on each request. Saving a key is an explicit operation with `expectedLifetime: string | null`, compared inside the guard. Every successful save, including the same API-key value, creates a fresh lifetime and replay key. Removal checks the current lifetime and deletes the bundle. Re-add creates new randomness. No request lazily creates or repairs a key. A stale UI save refuses instead of overwriting a concurrent change.

The proposed `auth.lock` is an exclusive-create guard held only for the synchronous read/validate/merge/atomic-rename operation; reads that establish a replay context use the same guard. Every updated `writeAuth` participates. Generic patches containing the reserved field refuse; migration recomputes `planSecretsMigration` from the current store **inside** the guard. A busy, inaccessible or orphan guard refuses without retries, age-based reclamation or touching Q3's separate `.reclaim` protocol. Recovery requires stopping all Wisp writers before inspecting an orphan. The guard is released on failure; the existing tmp/rename store retains its corruption and failed-write protections. [Node exclusive-open semantics](https://nodejs.org/api/fs.html#file-system-flags).

| Lifecycle | Selected behavior |
| --- | --- |
| Same bundle after process restart or host switch | Resume with the same key and lifetime. “Hosts” here means the TUI and extension processes sharing this local Wisp home. |
| Missing/invalid bundle, key removal, Provider/Target absent | Refuse; no fallback or new conversation. |
| Replacement, including identical key bytes; removal then re-add | New lifetime/key invalidates all earlier envelopes. |
| Borrowed `keyId`, environment credentials, other credential source | Unsupported in the first Gemini Provider. The fixed owner is `gemini-api`; `GEMINI_API_KEY` is not read as fallback. |
| Two cooperating writers | Exclusive guard plus expected lifetime yields one winner; loser is busy or stale. Sibling auth fields remain preserved. |
| Older/unmanaged writers, manual rollback/backup restore, shared/network filesystems | Not qualified by this proof. The guard is cooperative; restoring an entire old bundle can restore old replay authority. No anti-rollback database is claimed. |

The injected private context is `{ lifetime, key, credentialBinding }`, with `key` the persisted replay key and `credentialBinding = HMAC-SHA256(key, "gemini-api\0" + apiKey)`. It is secret material, never telemetry or a client field. The metadata lookup necessarily reads the auth file, including the key, but returns **no API bearer**. “Zero credential callbacks” below does not mean zero secret-file reads.

Credential resolution compares this entire expected context against a fresh guarded read and returns only the matching API key. Check again immediately before dispatch and after the complete result, before emitting an envelope or calls. A concurrent change between validation and resolution refuses before backend execution; after dispatch it suppresses delivery. No lock spans network IO. Rotation cannot undo an already-dispatched request or guarantee cancellation of Google compute/billing.

### Exact instruction subset

Identical flattened strings with changed original boundaries refuse. Object-key order is canonicalized; string contents and array order are exact JSON values, not normalization of instruction text. The projection is an explicit compatibility loss, not a proof that the model follows a native hierarchy.

### Session, replay and callback order

Read the HTTP `rawHeaders` pairs. Deliberate session spellings are case-insensitive `session-id` and `session_id`; each may occur once. Values must be plain UUID-shaped strings, normalized to lowercase. At least one session spelling is required. If both exist, they must agree. Optional `thread-id`/`thread_id` must also agree with that session. Duplicate spellings, comma-joined values, malformed/missing/conflicting aliases refuse. Thread-only and `prompt_cache_key`-only requests refuse. Cache keys and metadata are never session identity.

Order: **explicit custom-Responses route → session validation → supported source request/instructions/tools → replay-context lookup → envelope authentication/scope/history/visible batch/result validation → complete A2b request validation → credential resolution/current check → one backend request → complete response/current check → envelope and visible output**. Early supported-shape and session refusals have zero metadata, bearer and backend calls. Authentication/history refusals have zero bearer/backend calls. Rotation deliberately injected between validation and credential resolution has **one** bearer callback, **zero** backend calls. These are distinct claims.

The envelope uses AES-256-GCM with a fresh 12-byte nonce and 16-byte tag, versioned framing, and authenticated Provider/model/key-owner/session/lifetime/credential-binding/policy scope. Its payload holds a version, prefix binding and the complete validated result, including terminal status and original model steps. The diagnostic caps plaintext at 65,536 bytes and 64 model steps, refusing oversize rather than truncating. These are local qualification limits, not API limits. They must remain explicit or be separately requalified in production.

Visible output is derived from the complete validated steps. Every original call ID, argument value, thought/signature and step order is retained; tool names use the existing Responses registry mapping, including ordinary namespaced functions. Current proof refuses custom/search/hosted tools, strict-function-schema guarantees, multimodal input/results, compaction, unsupported controls and unknown/native opaque state. A complete result batch must follow its authenticated visible call batch, with one result per original ID. Uncarried assistant/model history and interrupted/altered visible output refuse. Per-output transport `id` and completed `status` may be omitted by the client when comparing the visible batch; original instruction/input-prefix IDs remain bound.

The synthetic encoder is not a production event encoder. Production must retain the A2a native carrier placement/echo contract, buffer and validate full A2b results before tools, and preserve native passthrough/generic rejection on other Providers. A client deleting its entire prior transcript still cannot be distinguished from a new stateless request; no hidden conversation database is introduced.
