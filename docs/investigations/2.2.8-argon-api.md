## Public contract pinned

The beta schema lists `gemini-4-argon`; `InteractionsInput` includes `StepList`, and `FunctionResultStep.call_id` identifies the original function call. The documented direct-model endpoint is `POST https://generativelanguage.googleapis.com/v1beta/interactions`. Stateless requests must explicitly set `store:false`. The stateless example replays complete returned steps; thought signatures and ordered function calls cannot be reconstructed from visible text alone. [Beta schema](https://ai.google.dev/static/api/interactions.openapi.json), [stateless function calling](https://ai.google.dev/gemini-api/docs/function-calling#stateless-function-calling).

Argon supports low/medium/high, default medium. The thinking guide requires preserving opaque thoughts in history. These published capabilities do not establish account entitlement. One `system_instruction` string does not provide a separate developer hierarchy. [Thinking](https://ai.google.dev/gemini-api/docs/thinking), [instruction configuration](https://ai.google.dev/gemini-api/docs/text-generation#system-instructions-and-other-configurations).

## Carrier established by the proof

The diagnostic places one `reasoning` item with empty summary and `encrypted_content` beginning `wisp-argon.v1.` before the visible response items. Its authenticated AES-256-GCM payload includes version, Provider/model/session scope, a digest of the prior history, a root-instruction digest, full serialized model steps, and the expected visible projection. A public synthetic test key is used only in ignored diagnostics. This is authenticated encryption, not base64 treated as a trust boundary.

The decoder authenticates, checks scope/bounds/version/types, compares the complete visible batch and preceding history, then replays the full model steps verbatim as JSON values. It validates one complete set of results against original call IDs. All remaining request content still passes through the unchanged source parser. Unknown/native opaque state remains unsupported. Prototype limits are 64 model steps and 65,536 plaintext envelope bytes, with explicit rejection rather than truncation; these are proof limits, not published Google limits.

**Observed session header:** native 0.159.2 sends `session-id` and `thread-id`, not `session_id`. The experimental harness used the actual `session-id` UUID; it did not substitute `prompt_cache_key`. A production integration must validate supported header spellings and refuse conflicts/missing identity. Existing product header handling was not edited here.

The proof preserves developer/system messages and their positions separately, and records `instructionTranslationQualified:false`. It does not silently map that sidecar into a Google instruction field. It also does not qualify compacted history, multimodal/built-in-tool steps, custom-tool projections, other client versions, signed Desktop, Claude or VS Code. A caller that removes the entire prior transcript cannot be distinguished from a new stateless request by an absent envelope alone; no hidden server history is claimed to solve that limitation.

## A2b: stateless core and one-request transport

Observed **2026-10-14**, relay leg 15, starting at `f5d51ce48805258a9ed071aea2ed20246d680f4e`. **Verdict: `pureCoreEstablished` with synthetic fetch only.** [Request/result validation](../../packages/core/src/geminiInteractions.ts) and [transport](../../packages/core/src/geminiInteractionsClient.ts) are unregistered modules. This does not extend A2a's client qualification, instruction policy or production admission.

The core sends exactly `gemini-4-argon`, low/medium/high effort (default medium), `stream:false`, `store:false`, `background:false`, and an optional positive output limit no greater than **65,536**. The caller supplies an already-resolved single instruction string. Tool definitions retain their existing `ToolSpec` names/schema; absent options remain absent.

Supported steps are text `user_input`/`model_output`, thoughts with optional signatures/text summaries, external function calls, and complete original-ID function result batches. All supported step objects, ordering and opaque strings survive unchanged. Duplicate/orphan/missing results and interruption within a result batch fail. Unsupported steps/content/options, annotations and step-level errors fail explicitly. The subset preserves schema optionality for content, signature and summary; it is deliberately narrower than the full beta API. It rejects non-JSON values, sparse arrays and executable serialization instead of silently dropping data.

Successful output must contain an explicit terminal status and a complete step array. `requires_action` requires at least one original external function call; `completed` cannot conceal outstanding calls. Incomplete/failed/cancelled/unknown states, unknown output and malformed usage fail before calls reach the consumer. Usage preserves the provider's optional fields verbatim: input is prompt/context tokens, cached is the cached part of the prompt, output is generated-response tokens, thought is thinking tokens, tool-use is tool-prompt tokens, and total is the provider's overall total. These counters are neither added together nor converted to zero-filled `BridgeUsage`.

Transport validates before IO, accepts an injected API key, and makes at most one POST to the fixed beta URL. Redirects and automatic retries are refused; safe HTTP status and parsed Retry-After milliseconds survive without upstream bodies/headers/exceptions. Cancellation is checked before dispatch, after body completion and after asynchronous cleanup. This promises only local cancellation/delivery suppression, not cancellation of Google compute or billing.
