# Wisp 2.2.12 / VS Code companion 1.14.9

This patch fixes native Codex, Anthropic and Grok context usage reporting in VS Code Copilot. The advertised context capacity was already present, but actual usage was being discarded by the adapter.

## Changes

- Emit Copilot's supported usage data part for all three native providers. Prompt totals include uncached input, cache creation and cache reads exactly once; cached-read counts remain available separately.
- Preserve Anthropic's initial input/cache fields when its final streaming update reports only output tokens. This shared-client correction also reaches terminal and extension Bridge consumers.
- Keep missing usage absent, ignore invalid numeric reports, and preserve real zero usage and tool-only response accounting. No new tokenizer, credential handling, capacity override or permission change.

## Verification and limits

The implementation passed **2,141 core tests**, including **39 native-provider tests** with **21 new usage regressions**, plus core typechecking and extension/webview compilation. The regression cases cover cached input, tool-only replies, missing usage, true zero usage and malformed counts, including updates that would otherwise overwrite previously valid values.

A real VS Code **1.146.0** development host exercised Codex GPT-6 Astra, Anthropic Claude Sonnet 4.6 and Grok 4.5 through the extension-host API. Each received two synthetic turns with prompt counts 100 then 200, output 10 and the expected cached-read detail. All six passed without real credentials or provider network traffic. The user additionally confirmed the live GPT-6 Astra Copilot meter at **5%**, replacing the previous 0% reading. Live Anthropic/Grok UI meters were not separately exercised.

Release verification also passed **191 TUI tests** (1,027 assertions), both package typechecks, all **34 TUI span captures**, VSIX packaging and the compiled Windows launcher/Responses and signed Desktop package smokes. Span changes are limited to the version string.

CodeRabbit completed the five-file implementation review with zero findings. Release metadata, rebuilt packages and native platform checks are separate gates before publication. The existing release workflow builds and smoke-tests Windows x64, macOS arm64/x64 and Linux x64 before publishing.

Prior qualification limits remain: classic Local live sign-in, forced Claude ANY tool choice, all variants, live compaction and full-window generation are not newly qualified by this accounting fix. See [2.2.11 limits](v2.2.11.md). Publication does not install or restart running clients.
