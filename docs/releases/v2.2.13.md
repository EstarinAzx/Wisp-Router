# Wisp 2.2.13 / VS Code companion 1.14.10 / wisp-slot 1.7.6

This release gives Claude and Codex launchers context budgets derived from the selected Wisp Target rather than an unrelated native model default.

## Changes

- `claude-wisp` launches installed Claude Code with the Target's exact context budget, including 500K limits. Signed profiles bind the budget to the Target; changed routes and unsafe model switches are refused before generation. Change Targets by exiting and relaunching/resuming with an explicit alias. Unknown limits remain an explicit conservative fallback.
- `codex-wisp` and Desktop catalogue setup use Antigravity's exact account model limits and preserve Codex Targets' separate default and maximum windows. Native Codex model switching remains available. Desktop admission and vision restrictions are unchanged.
- Antigravity credential refresh and metadata discovery share a four-second deadline. Account metadata skips unnecessary project bootstrap. The existing auth manager persists refreshed credentials with its account-change guards; failed refreshes preserve the old bundle, and account changes before capability consumption discard stale metadata. No browser sign-in is started, and native Codex authentication is untouched.
- Wisp's Anthropic User-Agent and billing-version stamp advance together to 2.1.322. This does not install or update Claude Code.
- The slot statusline recognizes generated Claude launch identities.

## Verification and limits

The release candidate passed **2,158 core tests**, **215 terminal tests**, both package typechecks, companion compilation, VSIX packaging and **34 version-only TUI span captures**. Compiled and packed-npm launcher/Responses and signed-Desktop smokes passed on Windows. The VSIX's extension and webview bytes match the verified build, and the npm Windows archive contains the verified binary. Native four-platform builds and packaging smokes run on the PR before merge.

Installed Codex 0.167.1 source/compiled checks use isolated homes and synthetic loopback traffic. They cover same-conversation model switching, settings preservation, native overrides and the 95% usable-context allowance: 1,048,576 reports 996,147 usable tokens; 500,000 reports 475,000. A Codex 272,000 default stays 258,400 usable unless overridden, with its 872,000 maximum allowing 828,400 usable tokens. Unknown metadata retains native fallback behavior, which is not proof of backend capacity.

A live metadata-only check refreshed the existing Antigravity credential through the production manager and confirmed Carbon (`gemini-4-carbon-high`) at 1,048,576 tokens and Grok 4.7 at 500,000. It completed in about 1.5 seconds; config and unrelated credentials remained unchanged. This is catalogue evidence, not full-window generation qualification.

The earlier merged Claude work passed source and compiled checks with installed Claude Code 2.1.322 at 128,000/400,000/500,000/1,000,000-token budgets, including refusal of a model switch that would invalidate the budget. Those checks use synthetic loopback providers. See [Claude launcher behavior](../claude-wisp.md) and [Codex context behavior](../codex-wisp.md#context-windows).

Full-window inference, automatic compaction end-to-end, the new Anthropic stamp's live acceptance, and a fresh Desktop UI check are not newly qualified. Existing live Local sign-in and forced Claude ANY tool-choice limits remain. Publication does not install or restart running clients.
