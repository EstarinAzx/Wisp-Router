# Wisp 2.2.8 / companion VSIX 1.14.5 / Slot 1.7.5

This candidate adds Argon through an existing Antigravity subscription, explicit account-quota refresh, and clearer Antigravity compatibility controls. No separate Gemini API key or approval-key enrollment is required.

- Antigravity discovery now includes `gemini-4-argon-low`, `gemini-4-argon-medium` and `gemini-4-argon-high`. Each is a separate model with a fixed reasoning tier.
- The Responses adapter retains original model state in authenticated encrypted conversation items. Original tool-call IDs, caller history and complete output must match on continuation. Incomplete output, altered state, changed account identity or an unsupported tier is refused.
- Signed Desktop aliases can use those exact targets after explicit `hoist-developer` opt-in. Native choices retain precedence and their own sign-in. Strict mode remains the default; hoisting makes developer notes global and does not preserve their original placement or temporal scope.
- `/quota` and `wisp quota` read the latest valid local account-usage snapshot. `quota refresh [anthropic|codex]` explicitly refreshes a supported signed-in account, with a shared five-minute cooldown. Slot reads the same account-bound cache without making requests. Unknown or stale readings are not presented as fresh quota.
- `/antigravity-compat` is available in the TUI with visible status, consequences and error feedback. The Claude Messages fallback remains off by default; start a new conversation after changing it.
- Malformed Antigravity token refreshes cannot erase a saved sign-in. Concurrent sign-in changes are checked before persistence and before Argon output is delivered.

Argon currently requires the Responses protocol and preserved encrypted reasoning items. Messages, Chat Completions and the VS Code native chat surface are not newly qualified for Argon. The companion carries the same Bridge implementation. No API-key fallback is exposed by this release.

The live subscription check completed a two-turn parallel-tool conversation on each of the three exact tiers, preserving original state and IDs. Native signed app-server checks cover tool continuation, fixed-tier catalog metadata and fresh-process conversation resume against a synthetic backend. Actual VS Code extension-host activation also passed. These checks do not establish the interactive Desktop effort picker's appearance or selection persistence, nor guarantee provider-internal reasoning allocation. That interactive observation remains an open release-acceptance item; this candidate is not yet published or accepted as complete.

Cancellation is cooperative. Wisp does not promise that a disconnected client forcibly stops remote generation. Restoring identical subscription credentials and Bridge secret restores the same replay identity; a new refresh identity, project or Bridge secret requires a new conversation.
