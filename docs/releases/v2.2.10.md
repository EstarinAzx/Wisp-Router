# Wisp 2.2.10 / VS Code companion 1.14.7

This release fixes native VS Code provider integration, model context budgets and MCP tool compatibility.

## Changes

- **Antigravity accounts and discovery:** native sign-in/out controls, OAuth-backed model lists and protection against stale account/model results.
- **Antigravity native chat:** one shared adapter for discovered text/chat models, including Argon and Carbon, instead of a per-model allowlist. It preserves authenticated reasoning/tool state through classic and Local continuations, forwards supported image inputs and retains safe capacity failover.
- **Correct context budgets:** Antigravity uses the account's reported context/output limits. Codex automatically uses its advertised maximum, falling back to its known default when no maximum is provided. Explicit per-model overrides remain bounded. Public API limits and native Codex configuration are not substituted for account metadata.
- **MCP tool compatibility:** native Codex/Grok preserve optional fields and open-ended tool parameters with non-strict Responses schemas, fixing the Pylance LSP `params` rejection. Tool permissions and execution remain with the native host.

## Verification and limits

The final source passed **2,081 core tests**, **201 TUI tests** (896 assertions), core/TUI typechecks and extension/webview compilation. Independent reviews covered provider parity, native replay and Local continuation, dynamic models, GPT context selection and the MCP schema repair. Material findings were corrected with failing-then-passing regressions. User smoke tests confirmed basic Argon, Carbon and Codex chat; the native picker displayed account-backed 1M and 872K limits. These observations do not establish full-window generation or every model/tool combination.

Native Antigravity state requires VS Code **1.145.3+**. Local continuation is bounded to 32 checkpoints / 16MiB of serialized history and needs a new chat after reload or eviction. Classic history retains encrypted per-turn packets. Image-generation output and Antigravity Inquire remain unsupported. Real tool-image results and interactive compaction are not newly qualified. Existing Bridge admission and Desktop protocol **5** are unchanged.

The release workflow builds and smoke-tests Windows x64, macOS arm64/x64 and Linux x64 artifacts before publishing. The companion VSIX is packaged from the same release source.

The release-preparation run exposed a collision between OAuth test files sharing fixed callback ports:
`authLifecycle.test.ts` timed out in Antigravity callback cleanup. The isolated callback suite passed;
core test files now run serially so independent workers cannot contend for those ports.

Publication verification: [release workflow 43021318794](https://github.com/EstarinAzx/Wisp-Router/actions/runs/43021318794)
passed all four native builds and publication. The downloaded VSIX and Windows executable match their
GitHub digests, the VSIX bundle matches the tested build, and the published Windows smoke check passed.
The npm dispatcher tarball passed its integrity check. Registry visibility initially lagged publication;
final checks confirmed the dispatcher and all four platform packages at 2.2.10. The published dispatcher
also successfully downloaded and ran the exact Windows binary through its existing fallback in an
isolated home. No installed clients were changed.
