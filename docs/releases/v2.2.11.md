# Wisp 2.2.11 / VS Code companion 1.14.8

This release separates chat diagnostics from `wisp serve` and fixes two reproduced Antigravity failures in the VS Code Copilot SDK/Agent Host harness.

## Changes

- **Session logs:** `wisp logs` lists recent sessions; `wisp log <session-id> [-f|--follow]` reads one. TUI `/show logs` opens the same session list, and `/show-log` remains an alias. Readers work across terminal and VS Code hosts without starting another Bridge. `wisp serve` prints lifecycle events rather than chat traffic.
- **Bounded diagnostics:** session files contain safe metadata and outcomes, excluding prompts, responses, tool arguments/results, credentials and replay packets. The store retains at most 128 sessions, with 256 KiB per file plus one rotation. The default recent window is 30 minutes; request activity does not establish whether a remote chat tab is still open. Host instances have separate stream identities.
- **Copilot SDK continuation:** full-history SDK turns can drop response-ID markers. The native adapter now also carries the same authenticated replay packet in encrypted reasoning. Missing, changed, duplicate or conflicting state remains rejected.
- **Claude native tool replies:** accept terminal `OTHER` only when the response contains well-formed tool calls and the returned Claude model exactly matches the request. Default Bridge validation remains STOP-only; truncation, safety, tool-ID and account/model/conversation checks remain intact.

## Verification and limits

Both reported failures were reproduced in VS Code **1.146.0** / Copilot **0.74.0**. After the fixes, actual SDK UI/live transport tests for **gemini-4-carbon-high** and **claude-opus-5-5-high** each read a controlled file, returned its expected value, and answered the following user turn. Regression tests cover both failures and authenticated-state rejection. Session logging was tested with isolated cross-process requests and readers.

The isolated classic Local UI required GitHub sign-in and stopped before transport; its real API synthetic continuation checks passed. A direct Claude forced `ANY` tool-choice probe returned HTTP400; automatic tool selection is the qualified path. These results do not qualify all variants, live compaction, full-window generation or every model/tool combination. Existing broken chats require a new chat. Native Antigravity state requires VS Code **1.145.3+**; image-generation output and Antigravity Inquire remain unsupported.

Local release verification passed **2,120 core tests**, **187 TUI tests** (1,015 assertions), core/TUI typechecks and extension/webview compilation on Bun **1.4.2**. All **34 TUI span captures** match after recapturing the version change. The **1.14.8 VSIX** contains the tested extension bundle; the **2.2.11 Windows binary** passed isolated launcher/Responses and signed Desktop package smokes, plus version and empty-session-list checks. These package checks use local fixtures and do not extend live-provider qualification.

CodeRabbit and remote integration are separate release gates. The Release workflow builds and smoke-tests Windows x64, macOS arm64/x64 and Linux x64 on a pull request; publication runs only on a version tag. No tag, publication or real-client installation/restart is part of this preparation.
