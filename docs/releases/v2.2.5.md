# Wisp 2.2.5 / companion VSIX 1.14.2

Adds signed-in Codex Desktop voice transport, qualified opt-in Antigravity routing and the terminal commands `/gpt-desktop on` and `/gpt-desktop off`. Installation and running-Bridge handover remain separate actions.

## Desktop routing

`/gpt-desktop on` uses the existing journaled setup with Antigravity compatibility enabled; `off` restores Wisp-owned native settings while preserving unrelated later edits. Neither command starts, stops or replaces the Bridge. A current serving Bridge is required for enable, and Desktop must restart after configuration changes.

Only `antigravity/gemini-3.8-flash-tiered` is qualified. Its compatibility mode preserves accepted developer text and relative order but moves the notes into the global instruction block. **Original instruction placement and temporal scope are not preserved.** Native model names retain native routing and sign-in. Explicit system turns, meaningful effort controls, images, hosted tool execution and opaque native reasoning/compaction replay remain unsupported on this Antigravity route.

Original provider tool IDs and exact custom-tool input/results are preserved. Source-boundary checks refuse interrupted, incomplete, duplicate and unknown result groups. Runtime policy rejects unqualified targets and revokes access when compatibility is disabled, including for stale catalogs.

## Voice and provider behavior

Native voice uses the existing ChatGPT sign-in and speech service, with the selected Wisp model handling backing text/tool turns. It does not turn external models into speech models. The user confirmed live Desktop voice; account entitlement, microphone and playback remain native responsibilities.

Antigravity status/retry handling preserves upstream failure status and supported retry timing. The earlier production-only 429 cause remains unknown. Grok image checks passed and the user reported working behavior, but the original incorrect-description report was not reproduced and is not claimed fixed.

## Upgrade

Protocol **5** requires matching setup and serving Bridge: terminal **2.2.5**, or companion **1.14.2** when VS Code hosts the Bridge. A protocol-3 setup needs journaled `disable` then `enable` to install voice settings; a catalog refresh alone does not migrate those settings. Coordinate the Bridge handover and configuration migration around active clients sharing `CODEX_HOME`. Do not replace the user's current working Bridge as cleanup.

For strict instruction policy use the lower-level `wisp codex-desktop` commands described in [Desktop setup and rollback](../codex-desktop.md). Existing native credentials and unrelated configuration must remain intact. Installation and updating an already running process are separate actions.
