# Wisp 2.2.6 / companion VSIX 1.14.3

This patch preserves caller cache metadata that the Grok and API-key adapters previously discarded, and adds Antigravity diagnostics for investigating stalled cache reuse.

- Responses requests retain explicit `prompt_cache_key` values through Grok and the common API-key adapter. No key is invented when absent.
- Grok proxy requests reuse validated conversation identity from Responses headers and Claude Messages metadata. Cache keys remain separate from session identity; calls without identity retain per-request isolation.
- Antigravity logs correlate request IDs, upstream host attempts, reported cache usage and HMAC fingerprints of final prompt components. Fingerprints use a process-local secret and do not expose raw prompts, tool definitions, attachments, credentials or account/session IDs.
- Missing usage is recorded as unknown. Fingerprints cover the full history plus the first 128 individual contents; comparisons are valid within one process.

[How to read the cache diagnostics](https://github.com/EstarinAzx/Wisp-Router/blob/v2.2.6/docs/provider-caching.md)

Desktop protocol remains **5**. Routing configuration, Desktop enablement, Antigravity instruction hoisting and provider request semantics remain unchanged. The companion bundles the same shared Bridge fixes.

Verification uses offline regression tests, synthetic/loopback upstreams and native package checks. These fixes and diagnostics do **not** establish improved live cache-hit rates, lower subscription usage, universal endpoint support for cache controls, or a resolved cause for Antigravity's observed plateau.
