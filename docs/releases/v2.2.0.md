# Wisp 2.2.0 / companion VSIX 1.14.0

Release candidate: actual Codex desktop acceptance, other-platform native CI artifacts and publication remain pending. This document is the release-notes source, not a publication announcement.

`wisp codex-desktop enable|status|refresh|disable` provides opt-in persistent Codex configuration with ChatGPT sign-in retained by the native client. Start the current Bridge first, enable the integration, then restart Codex. Refresh updates picker entries; exact route target edits apply live. Disable restores the previous owned settings while preserving unrelated edits.

Current candidates require signed desktop protocol 2. Antigravity Targets are excluded from this surface with explicit override/alias notices; other clients and stored routes remain unchanged. Native choices mirror ordinary native-client export rather than bundled-only rows. Alias refresh reuses a labeled saved native view; native/account rediscovery requires disable/discover/enable. Original custom catalog overrides must be cleared in native mode before enable. A selected Wisp-only default is narrowly restored on disable; effort/profile preferences remain and may require user action.

Automatically attached unused hosted-search declarations are omitted only on supported signed external routes with automatic tool choice. No hosted search capability is claimed, no global search setting changes, and forced/executed search or opaque history still fails. Positioned developer instructions are not consolidated or reordered.

Wisp Aliases and exact native model overrides use their configured Provider/model. Unoverridden native models use the fixed native OpenAI transport. Unknown IDs fail locally. Native account credentials, external Provider credentials and the local Bridge secret remain separate; credential-bearing redirects are refused.

The standalone Windows asset is `wisp-v2.2.0-win32-x64.exe`. Other native CI assets are `wisp-v2.2.0-darwin-arm64`, `wisp-v2.2.0-darwin-x64` and `wisp-v2.2.0-linux-x64`. npm shell/platform versions are **2.2.0**. The required companion is **wisp-1.14.0.vsix**; an already installed extension is unchanged until updated and reloaded. **wisp-slot is unchanged**.

After publication, npm installation is `npm i -g wisp-router@2.2.0`; npm shims require Node.js. Standalone binaries need neither Bun nor Node unless the separately installed Codex CLI itself is an npm installation. The companion installs with `code --install-extension wisp-1.14.0.vsix`.

Candidate verification includes CLI **0.154.0** app-server production-path text/tool/route/cancellation checks with synthetic auth, isolated copied binary/npm lifecycle checks and archive/bundle inspection. Packaging smoke uses a deterministic catalog-export fixture; it does not prove actual desktop UI behavior or live upstream success. The older **0.153.4** native check is retained unchanged. HTTP Responses is supported; WebSockets and unsupported external hosted-tool/image capabilities are not advertised.

See [desktop setup and rollback](../codex-desktop.md), [launcher compatibility](../codex-wisp.md), and the terminal/extension changelogs. Publication must wait for recorded actual desktop picker, retained login and selected route after restart, plus native CI and exact asset checks.
