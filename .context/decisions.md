- [[2026-07-30-a-quota-window-belongs-to-the-account-a-context-reading-to-the-conversation]] — **SHIPPED `5592f44`, released as `wisp-router@2.0.42` + `wisp-slot` 1.7.0:** `status.json` gains a **`providers` ledger** (every Provider that reported utilization in the last 24h) because the two numbers #171 stored side by side have **different owners** — context fill measures *this conversation* against *this model's window* and dies with the conversation, while a quota window measures *the account* against *time* and outlives every conversation. One freshness bound for both meant ageing out the context reading also deleted a perfectly good account reading, and a route switch silently destroyed data nobody could re-read (quota only arrives on a response head, so the first Anthropic turn after a Codex one erased Codex's weekly figure as a side effect of tidiness). Three rules follow: only quota carries across a switch; the **active Provider is never in the ledger** (it *is* the top-level snapshot, and holding both renders one wire twice — as a live row and a stale row, which reads as two limits); and a stale snapshot **loses its `ctx` and keeps its meters**, demoted to a dimmed row stamped with the reading's age. The age stamp is what makes keeping it legitimate: **"never a confident wrong number" is not "never an old number" — it is never an *unlabelled* one**, and without the stamp the same data would be exactly the failure #171 exists to prevent. Bounded at **24h** (outlives 5h, covers most of 7d) and pruned on **read as well as write**, because nothing rewrites the file while nothing runs, so an idle machine would otherwise show yesterday's limits. Rejected: remembering the whole entry per Provider (another Provider's old context percentage describes a window this session is not spending), and polling Providers for quota out of band. Reversible in one line — an optional field on regenerated telemetry, which is also why 1.7.0 renders against any Wisp version, just with fewer rows

- [[2026-07-30-the-antigravity-arm-is-not-a-copy-of-the-anthropic-arm]] — **SHIPPED `915d415` (#191):** the Anthropic door's fourth arm mirrors the three above it only where the wire agrees, and four divergences are deliberate. **The FULL system rides, not `systemSplit.stable`** — the Anthropic arm prefers `stable` because the #139 split places a **cache breakpoint** and the volatile tail threads separately as `systemSuffix`; this wire has neither, so `stable` alone is not "the cached part", it is *the system prompt with its tail deleted*, and copying the arm three lines above (the most natural tidy-up there is) silently drops the mid-session `<system-reminder>` append from every request with nothing erroring. **Thought parts now ride the thinking channel** (the door renders them; the OpenAI door reads `text`/`tool_call` only and still sees nothing) but **`thoughtSignature` is not forwarded** as an Anthropic `thinking.signature` — it is *this* wire's replay token, the Anthropic field means a different thing, and the only consumer would be a replay path that does not exist (`AntigravityTurn` has no `rawContent` channel, so a returned block dies before the payload builder); an empty signature is what the Anthropic OAuth wire already sends through this same encoder. **Documents are wired beside images** — one attachment shape on this wire, a PDF differs from a PNG by mimeType alone, two lines, and leaving it out would repeat the door's old silent-vision hole with PDFs. **No effort, no strictness flag, no `mapOAuthStream` hop** — Gemini bakes reasoning into the model id, `buildAntigravityTools` already cleans Claude Code's schemas, and the stream already speaks `BridgeStreamEvent`. - [[2026-07-30-a-classified-verdict-rides-on-the-error-not-its-message]] — **SHIPPED `6a7e0fe` (#190):** Antigravity is the first `ProviderExecutor` record to answer a rate limit as **429** instead of leaving it a 502, and its `classify` hook reads the verdict **off the thrown Error** (a property `antigravityApiError` attaches) rather than out of the message — deliberately breaking the house style, because for *this* Provider the message genuinely cannot round-trip it: a 429 the pure layer **declined** renders as `Antigravity API error 429: <raw upstream body>`, and that body says `RESOURCE_EXHAUSTED` and `RATE_LIMIT_EXCEEDED` **exactly like a classified one** — the two cases differ by a *number that was parsed and then discarded* (the retry delay vs the 3s instant-retry threshold), so no needle separates them. Codex is not analogous: its two cases use different vocabulary (`usage_limit_reached`), so a string matcher there reads a real distinction — the difference is in the **wire, not the taste**. Guessing is **asymmetric**: guessing "declined" wastes two retries then answers right, guessing **"classified" kills the bounded retry** and loses a turn to a rate limit that had already expired — so a mechanism that cannot be wrong beats one that is usually right. The control is the whole argument: swapping in the natural message classifier leaves **990 of 991 green**, failing only `leaves a below-threshold 429 to the bounded retry` — every "does it answer 429" test passes, because the wrong implementation answers 429 for *everything*; the test that pins this decision is the one asserting a **non**-classification, and a suite written only around the feature's happy claims ships the guess. Cooldowns widen by giving `ProviderCooldowns` a **second door** (`noteQuotaWindow`) onto the SAME long channel rather than teaching `parseUsageLimitReset` a second dialect — additive, so no other Provider moves, and the separate-maps property holds structurally. Deliberately **not generalised**: the carrier is named for its one producer; lift it when a second Provider needs one. **Verified live** — a real `claude-sonnet-4-6` 429 carried `cooldownSeconds: 118540` against an independently-recorded reset **118,548s** away, so the horizon is the server's own to within request latency
- [[2026-07-29-a-retyped-sse-fixture-cannot-catch-a-crlf-framing-bug]] — **SHIPPED `c6f644a` (#189):** the first live Antigravity turn returned an **empty answer at HTTP 200** — clean `finish_reason: stop`, no text, no error, nothing logged — against a **971/971 green** suite that included 18 client tests over supposedly-captured wire bytes; the upstream frames SSE with **`\r\n\r\n`** and the shared `sseBlocks` split on the literal `'\n\n'`, a sequence that **never occurs** in a CRLF stream (the `\r` sits between the two `\n`), so nothing split, the whole response flushed as ONE block, `JSON.parse` of two concatenated documents threw, and `parseDataFrame`'s by-design swallow of a bad frame dropped **every** frame — the worst shape a bug can take, **indistinguishable from a model that chose to say nothing**; the tests were green because the fixture was built by **reading the capture and retyping its bytes**, which normalised CRLF to LF — every *content* assertion in it was faithful (real tool call, real signature, real usage), only the **framing** was wrong and framing was the one thing unasserted. The rule: **when framing is part of the contract, copy the bytes, never retype them** — a hand-authored fixture silently normalises whitespace and line endings, exactly the properties a parser depends on and a content assertion cannot see; make the separator a named visible constant (`const FRAME = '\r\n\r\n'`), never an incidental `.join('\n')`. Fix is `/\r?\n\r?\n/`, which matches `'\n\n'` identically so Codex and Anthropic are untouched — SSE permits CRLF, LF and CR, so the old literal was simply **wrong about the format** rather than tuned for one provider. Control: reverting the separator fails **5** tests including `expected [] to deeply equal ['TURN','_OK']`; before the fixtures were reframed to CRLF the same revert failed **nothing**. The wider lesson is about the gate — #189's coverage was genuinely good (six deliberate-break controls, the retry contract asserted against the **real** predicate rather than a copy) and none of it reached this, because all of it ran **downstream of the framing**: **live verification was not ceremony here, it was the only thing that could have caught it**, and gating a Provider on "tests pass" alone would have shipped one that silently answers nothing
- [[2026-07-29-antigravity-narrow-port-never-mint-opaque-tool-ids]] — **Spec #185 (grooms #174), tickets #186–#192, nothing implemented yet:** Antigravity lands as a **sixth Provider kind** at ~1,200–1,500 TS lines against the reference's **5,643 non-test Go lines** — both Bridge doors, all 13 models, VS Code picker deferred. Accepted regression: the model **re-reasons rather than resuming its thought chain** when a client mutates history. Four pieces port regardless (signature sanitize · pairing validate · unsigned-leading-call repair · function-response role normalize).
